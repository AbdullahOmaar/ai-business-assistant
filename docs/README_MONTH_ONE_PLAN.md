## How to use these documents

1. Treat them as a **proposal for review**, not as proof that tasks are complete.
2. At the start of each week, turn the relevant tasks into focused GitHub Issues and assign them to the appropriate contributor.
3. Keep one issue small enough to complete and review in roughly 1–3 sessions.
4. Link PRs, test results, official documentation, and learning notes to the issue.
5. At the end of each week, update progress based on evidence.
6. Change the plan when architecture decisions, availability, or actual results require it.

## Guardrails

- GitHub is the source of truth.
- No PR merges without Abdullah's explicit approval.
- No Firebase configuration changes, paid services, or production deployment are authorized by this plan.
- Do not store secrets or real customer data.
- A green check, test pass, deployment, or implementation must never be claimed unless it actually occurred.
